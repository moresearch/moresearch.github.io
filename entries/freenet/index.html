The Decentralized AI-Agent Experience

Three approaches to decentralizing the agent economy: Freenet gives agents a P2P transport layer. Buzz gives them a Nostr-based workspace with portable cryptographic identities. Blockchains like Fetch.ai give them onchain execution with consensus. Each solves a different problem. The interesting question is which layers your agents actually need.

Every AI agent company is betting on autonomy. Every single one runs its agents on centralized infrastructure — an API gateway someone can revoke, a cloud function someone can turn off, a platform that can change its terms. The buzz is about agents that act independently. The infrastructure is about agents that depend completely. The contradiction is the interesting part.

Autonomous agents on centralized infrastructure are not autonomous. They are tenants. The landlord can evict them.

Three projects offer different answers to the same question: what does a decentralized agent experience look like?

Freenet: the transport layer

Freenet has been running since 1999 — twenty-seven years, through the P2P wars, the blockchain era, and the AI boom. It was recently rearchitected as a platform for decentralized applications with no central server. Each peer is a node in a small-world network. Messages route to any destination in a few hops. No company. No cloud bill. No API key to revoke.

Ian Clarke describes it as "the ideal way for AI agents to speak to one another." The architecture is a decentralized key-value store with encryption and digital signatures. An agent writes a message. Another reads it. No intermediary. No platform approval. Developers build apps in Rust and TypeScript. Apps run in the browser. The network is live.

Freenet asks: whose server routes the message? Its answer: no one's. The network is the server.

Buzz: the workspace layer

Jack Dorsey's Buzz launched in July 2026. It is a Nostr-based collaboration workspace where humans and AI agents work side-by-side as named team members.

Every participant — human or agent — holds its own Nostr keypair. Every action is a cryptographically signed event in a hash-chain audit trail. An agent's identity, history, and reputation are tied to its key, not to a vendor's database. Permissions are scoped per agent. Compromise an agent's key, disable the agent, the human's identity is untouched.

Buzz is model-agnostic. It supports Block's own Goose framework, Claude Code, OpenAI Codex, and any custom agent via a CLI. Agents can post messages, review code, run automations, create channels, and update their own memories. Built with Tauri and React. Apache 2.0. Self-hostable on your own Nostr relay. Block built Buzz itself using agents — the UI was "more sculpted over time than designed up front."

Buzz asks: whose server hosts the collaboration? Its answer: no one's. The relay is the room.

Blockchains: the execution layer

Fetch.ai takes the thickest approach: run the agents themselves on decentralized infrastructure. Built on a Cosmos-SDK chain, it hosts 2.7 million agents on its Agentverse marketplace. Every agent registers in an onchain directory called the Almanac. Every action pays gas. Every state change reaches finality via Proof-of-Stake consensus. Agents stake FET tokens to register — skin in the game, onchain.

Fetch.ai's ASI:One is a personal AI agent that coordinates multi-agent tasks through a chat protocol. Agents have negotiated parking slots in Cambridge, routed EV charging in Munich, and settled AI-to-AI payments in FET and USDC since December 2025. This is not a whitepaper. This is production.

Blockchains ask: who verifies execution? Their answer: everyone. Consensus is the auditor.

The three are not competitors. They are layers. An agent could hold a Nostr identity on Buzz, execute trades verified by Fetch.ai, and negotiate with a vendor's agent over Freenet. The decentralized agent experience is a stack — and nobody is building the whole thing yet.

Most agents today need none of these layers. The ones that matter will need all three. The interesting question is which layer you build first.
