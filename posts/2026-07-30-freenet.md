The AI agent buzz is deafening. Every company is shipping an agent SDK. Every VC deck has a slide about autonomous AI. And every single one of those agents runs on centralized infrastructure — an API gateway owned by a company, a cloud function that can be turned off, a platform that can change its pricing or its terms or its mind.

> The buzz is about autonomy. The infrastructure is about dependence. The contradiction is the interesting part.

Three projects offer different answers to the same question: what does a decentralized agent experience actually look like?

## Freenet: the transport layer

[Freenet](https://freenet.org/) is a peer-to-peer network that has been running since 1999. It was recently rearchitected as a platform for applications with no central server. Each peer is a node. Messages route through a small-world network in a few hops. There is no company. No cloud bill. No API key to revoke.

Ian Clarke describes it as "the ideal way for AI agents to speak to one another." The architecture is a decentralized key-value store with encryption and digital signatures. An agent writes a message. Another reads it. No intermediary. No platform approval. Just peers.

> Freenet asks: whose server routes the message? Its answer: no one's. The network is the server.

## Buzz: the workspace layer

Jack Dorsey's [Buzz](https://www.youtube.com/watch?v=CHEMPZ87FLw) is a Nostr-based collaboration platform where humans and AI agents work side-by-side. Every agent holds its own Nostr keypair. Every action — a message, a code review, a merged PR — is a cryptographically signed event with an audit trail. Agents are not bots behind slash commands. They are named team members with portable identities that survive any single relay.

Buzz collapses chat, Git hosting, and AI orchestration into one open-source workspace. Built by Block. Apache 2.0. Self-hostable. The question it answers is not how agents talk to each other. It is where they work together — and who owns the room.

> Buzz asks: whose server hosts the collaboration? Its answer: no one's. The relay is the room.

## Blockchains: the execution layer

Warden, Fetch.ai, and the broader onchain agent ecosystem take a third approach: run the agents themselves on decentralized infrastructure. Smart contracts govern behavior. Consensus verifies execution. Tokens align incentives. The blockchain is not just the payment rail — it is the runtime. The agent's logic, state, and decisions are onchain, auditable by anyone.

This is the thickest form of decentralization and the most expensive. Every action pays gas. Every state change waits for finality. For agents that move money, the cost is justified — you want a trading agent's execution to be verifiable by the network, not by a single company's logs. For agents that move messages, the cost is overhead.

> Blockchains ask: who verifies the agent's execution? Their answer: everyone. Consensus is the auditor.

## The trade-off

|  | Freenet | Buzz | Blockchain |
|------|---------|------|------------|
| **Layer** | Transport | Workspace | Execution |
| **Identity** | Peer address | Nostr keypair | Wallet address |
| **Trust model** | Encryption + signatures | Cryptographic events | Consensus |
| **Cost** | Bandwidth | Relay hosting | Gas fees |
| **Best for** | Agent-to-agent comms | Human-agent collaboration | Financial execution |

The three are not competitors. They are layers. An agent could hold a Nostr identity on Buzz, execute trades verified by Warden, and negotiate with another agent over Freenet. The decentralized agent experience is not one project. It is a stack — and nobody is building the whole thing yet.

> The interesting choice is not which project wins. It is which layers you need. Most agents today need none of them. The ones that matter will need all three.
